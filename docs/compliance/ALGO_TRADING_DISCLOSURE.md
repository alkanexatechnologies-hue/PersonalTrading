# Algorithmic / Automated Trading Disclosure

## Warning (verbatim)

> Algorithmic or automated trading can result in rapid losses. Signals generated by this
> application are not a guarantee of execution price, profitability or successful trading.

The application makes **no** claims about expected or future returns. SEBI has specifically
cautioned investors about unregulated algorithmic-trading platforms making high-return claims.

## Current automation status — IMPORTANT

**This application does NOT place live orders with any broker or exchange.**

- `BrokerProvider` (`backend/data/brokerProvider.ts`) is a placeholder reserved for future
  order execution. It throws on use and is never wired into the data or execution path.
- The only automation present is the **AI Paper Desk**, a fully **simulated** paper-trading
  engine (`backend/paper/engine.ts`). It opens/closes *simulated* positions using live
  market data, real cost/slippage assumptions and honest P&L. No real orders are sent.

Because there is no live order execution, the automated-trading acknowledgement, risk
controls and emergency stop described below currently govern the **simulated** engine.
They are implemented so the controls exist and function, and so the same pattern can be
reused if live execution is ever added.

## Automated-trading acknowledgement (simulated engine)

Before enabling the simulated auto-trade, the user must explicitly acknowledge:

> ⚠️ AUTOMATED TRADING RISK
>
> Automated trading can result in rapid losses, including losses caused by market
> volatility, technical failures, stale data, connectivity issues, incorrect configuration
> or unexpected market conditions.
>
> [ ] I understand the risks and want to enable automated trading.  [ ENABLE AUTOMATED TRADING ]

The checkbox must be explicitly selected before automation is enabled.

## Risk controls & emergency stop (simulated engine)

- Maximum daily loss, maximum trades/day, maximum position size and maximum consecutive
  losses are surfaced in the Auto-Trading controls panel.
- An **Emergency STOP** immediately disables the auto-trade (no new simulated orders).
- The simulated engine additionally enforces built-in gates (e.g. daily-loss cap, heat cap).

## If live execution is ever implemented — REQUIRES external confirmation

Adding real order execution would require, at minimum:

- Broker API integration, order tagging and API monitoring — **REQUIRES BROKER CONFIRMATION**.
- Algo registration / exchange approval and algo-order tagging — **REQUIRES EXCHANGE CONFIRMATION**.
- Algo-provider arrangements and applicable SEBI algo-trading rules — **REQUIRES LEGAL/COMPLIANCE REVIEW**.
- A hard kill-switch verified against the live order path — **PENDING REVIEW**.

Until those are independently verified, live automated execution must remain disabled.
